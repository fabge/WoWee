# tools/

Everything here reads the repository and reports on it. Nothing here is part of
the client.

There are three kinds of thing in this directory, and the third column of the
table below says which one each file is.

**Sweeps pinned by `sweep_guard.py`.** Each prints a count of something that
should not exist, and `sweep_guard` fails the build when that count rises above
a pinned ceiling. This is one CTest entry (`sweep_guard`) and about three
minutes of the suite's three and a half. A sweep is pinned once someone has
confirmed it reports the fault it claims to - usually by putting the fault back
and watching it appear.

**Sweeps run by `tools_run_check.py`.** Everything else that is a sweep. It runs
them and checks only that they still run: a sweep nobody runs does not go stale,
it breaks, and a broken sweep is indistinguishable from a clean one.

**Libraries, generators and GUIs.** Not sweeps and not run by either. Named in
`NOT_A_SWEEP` in `tools_readme_check.py`, with a word on what each is.

## Running them

    python3 tools/<name>.py             # any single sweep, from the repo root
    ctest --test-dir build -R sweep_guard
    bash tools/validate.sh              # the whole suite, before a push

Several resolve their inputs against the working directory rather than against
their own path, so run them from the repository root. Some read extracted
Blizzard data that is not in this repository and report themselves as skipped
when it is absent - that is not a failure.

## Subdirectories

| Path | What it is |
| --- | --- |
| `tools/asset_extract/` | MPQ → loose files. A C++ tool, built as the `asset_extract` target. |
| `tools/editor/` | The standalone world editor. Built on demand: `cmake --build build --target wowee_editor`. |
| `tools/macos/` | Bundle, sign and install the `.app`. |
| `tools/android/` | The Android build's scaffolding. |
| `tools/auth_probe/`, `tools/auth_login_probe/` | Talk to a realm's auth server directly. |
| `tools/blp_convert/`, `tools/dbc_to_csv/` | One-format-to-another converters. |

Shell scripts: `validate.sh` is the suite; `link_local_data.sh` makes the links
the sweeps read the extracted interface through; `backup_assets.sh`,
`addon_events.sh`, `build-android-deps.sh` and
`generate_ffx_sdk_vk_permutations.sh` do what they are named.

`framexml_compile_check.cpp`, `framexml_emit.cpp` and `framexml_run.cpp` are C++
and are built as their own targets; they are the arms of `validate.sh` that run
the real interface against the real widget tree.
